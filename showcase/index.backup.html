Namespace Architecture

One Kubernetes cluster can organize resources into separate namespaces.

dev

Development workloads · NGINX Deployment · 2 replicas

prod

Production workloads · NGINX Deployment · 2 replicas

Resource names can be reused in different namespaces. Namespaces provide logical separation, not a complete security boundary by themselves.

Command Reference

# Inspect the active context
kubectl config view --minify

# List Pods in the current namespace
kubectl get pods

# Display resource labels
kubectl get pods --show-labels

# Filter by label
kubectl get pods -l app=web

# Add a custom label to a Pod
kubectl label pod POD_NAME owner=azeem

# Remove the custom label
kubectl label pod POD_NAME owner-

# Inspect development resources
kubectl get all -n dev

# Inspect production resources
kubectl get all -n prod

# List namespaces
kubectl get namespaces

Replace POD_NAME with an actual Pod name from your cluster.
